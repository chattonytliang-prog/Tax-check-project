# 报告积分计费

## 规则

- 普通账号首份新报告免费。历史报告计入首份；删除报告不恢复免费次数或积分。
- 之后每份新报告扣 200 积分。查看、导出、AI 润色同一份已授权报告不再扣分。
- 1 元对应 1 积分，充值 200 元对应 200 积分，刚好可生成一份付费报告。
- 管理员账号生成报告免费。管理员代入普通账号时按普通账号计费。
- 积分不得为负；调整积分必须由管理员操作，填写原因，并留下流水。界面上的二维码只是演示位置，不代表支付已接通。

## 上线顺序

1. 备份生产 D1 数据库。
2. 执行 `migrations/0009_report_points.sql`，例如 `npm run d1:migrate:points`。迁移可重复执行，并会为已有用户建钱包、为已有报告登记历史授权。
3. 执行 `migrations/0010_ai_daily_usage.sql`，例如 `npm run d1:migrate:ai-budget`。
4. 验证 `point_wallets`、`report_entitlements`、`point_transactions`、`ai_daily_usage` 已建立，并核对有归属的历史报告授权数量。无归属的旧报告保留原状，不自动指派给任何账号。
5. 部署前后端代码。不要先部署代码再迁移数据库。

如需展示真实收款码，可在前端构建时配置 `VITE_PAYMENT_QR_IMAGE_URL` 为经过确认的收款码图片地址。当前系统不会自动核验转账或自动加分；管理员核实实际到账后，在“管理员 -> 用户与积分管理 -> 调整积分”给对应用户增加 200 积分，并填写核实依据。没有配置该变量时，只显示不可扫码的演示标志。

正式的自动扫码收款需要单独接入支付服务商订单、签名回调、金额核验和幂等入账。不能凭用户点击“已付款”或上传截图自动加分。

## 接口

- `GET /api/points`：本人余额、首份免费状态及最近 50 条流水。
- `POST /api/admin/users/:id/points`：管理员积分调整，参数为整数 `delta`、非空 `note` 和每笔操作固定的小写 UUID `requestId`；同一编号重试不会重复入账，改用同编号提交不同内容会被拒绝。工作台请求需带 `X-Requested-With: tax-workspace`。
- `POST /api/reports`：首次创建报告须带 `X-Expected-Report-Cost: 0` 或 `200`，表示用户本次确认的积分费用。D1 事务内核对实际免费名额、登记授权、扣分并保存报告；报价已变化时返回 409，不会静默扣分。已有报告只允许相同请求重试或一次同源 AI 润色。
- `POST /api/ai/report`：仅可润色当前账号已保存的报告。

## 验证

- `npm run coverage:billing` 对积分账户、管理员调分、报告保存和 AI 报告入口这 5 个后端文件执行 100% 语句、分支、函数及行覆盖率检查。
- `npm run coverage` 是原有 `src/lib/*.ts` 的覆盖率检查，不代表整个前端和所有 Functions 的覆盖率；两个命令的统计范围不可混同。
